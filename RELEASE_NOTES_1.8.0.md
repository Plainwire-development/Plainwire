# Plainwire 1.8.0

Plainwire 1.8.0 adds an optional, privacy-preserving **service control plane** for operators of a configured Plainwire host. This is host administration, not per-server moderation.

## Service control plane

- Separate Cowboy listener and static control-plane UI; no admin route is mounted on the ordinary Plainwire listener.
- Disabled by default and loopback-bound by default.
- Production remote binding requires explicit opt-in, an HTTPS admin public URL, and secure admin cookies.
- Responsive Plainwire-styled operator UI for overview, users, hosted servers, host/runtime health, operators, and content-free audit history.
- Host telemetry covers BEAM/runtime memory and process pressure, database pool health, realtime/WebSocket/voice/call counts, cluster state, rate limiter state, media/cache pressure, upload state, TURN/native-call-health availability, and a non-secret configuration allowlist.

## Instance-bound verification

- No reusable administrator secret exists in source code.
- Every instance generates a local 256-bit secret and derives a public instance ID from it.
- First-owner bootstrap uses a one-time token generated by the running instance plus the owner's normal Plainwire account/password.
- Each operator receives a separate high-entropy verification key. Plainwire stores only an HMAC of that key under the local instance secret.
- Verification keys and one-time enrollment codes include the instance ID, preventing accidental cross-instance use before database authentication.
- Owner-issued enrollment and account-recovery codes are account-bound, expire, and are claimed under a row lock so one code cannot be redeemed twice concurrently.
- Verification-key rotation revokes the operator's current admin sessions.
- Role changes and operator removal revoke affected admin sessions and preserve a last-owner invariant.
- RBAC is meaningful rather than cosmetic: viewers receive aggregate host/overview telemetry, operators can inspect content-free service/account/server/audit metadata, and owners additionally manage operator credentials and roles.

## Host-local emergency recovery

- `PLAINWIRE_ADMIN_LOCAL_RECOVERY=true` is an explicit emergency mode for operators who control the host but have lost the final usable owner key or instance state.
- Recovery is rejected unless the admin listener is bound to loopback.
- The running instance prints a one-time recovery token; claiming it still requires a real Plainwire username/password.
- Successful recovery issues a fresh instance-bound owner key, revokes all admin sessions, and invalidates outstanding unused enrollment codes.
- One-time secret dialogs cannot be dismissed before the operator explicitly acknowledges saving the secret.

## Privacy boundary

The control plane exposes operational metadata and aggregate counts. It deliberately has no endpoint or database query for:

- message bodies or DM text;
- attachment contents;
- message search;
- private profile text such as bios;
- plaintext operator verification material.

Account and hosted-server pages expose identity/ownership/activity/resource metadata needed to operate the service without turning the panel into a communication-surveillance interface.

## Data and performance hardening

- Migration 29 adds normalized admin operators, sessions, one-time enrollments, and audit records.
- Added indexes for global message activity, per-user message metadata counts, and session expiry.
- Admin pagination and query lengths are bounded.
- Admin auth has independent rate limits, mutating requests require a separate CSRF token, and session cookies are HttpOnly + SameSite=Strict.
- Operator UI renders remote data through DOM text nodes rather than dynamic HTML interpolation.
- IP addresses and user-agent values used for admin-session/audit correlation are HMACed under the instance secret rather than stored raw.

## Realtime, calls, reactions, and mobile polish

- Reaction additions now create normal Plainwire activity notifications for the message author. Self-reactions and removals do not notify; recipient access is rechecked and repeated add/remove abuse is rate-bounded.
- Foreground reaction events refresh the activity feed, use the existing notification sound preference, and show a short toast; background tabs can use the existing browser notification path and deep-link back to the message scope.
- WebSocket health now detects half-open connections with a heartbeat/staleness budget and deliberately reconnects them so the normal sync/re-subscription path runs instead of waiting for a manual browser refresh.
- Successful WebSocket reconnects reconcile account/navigation state immediately. A low-frequency visible-tab safety sweep also refreshes global state and the active route to recover from rare missed events where the socket itself never visibly fails.
- Active calls periodically audit their remote audio path. Plainwire first repairs a suspended/replaced browser audio element, then uses the existing bounded peer-only rebuild path only after sustained missing/stalled receiver evidence. Mute/deafen remain local media-state changes and do not tear down the room.
- Browser online, foreground, and page-show transitions resume audio playback and immediately re-audit the active RTC room.
- The first-run guide now chooses actually visible mobile controls, avoids zero-size/hidden desktop targets, moves its guide card away from bottom-screen targets, respects mobile safe areas, and keeps long guide content scrollable instead of covering navigation.
- DM sidebar previews remain plain-text, one-line bounded summaries; attachment floods are collapsed into counts instead of rendering images/embeds in navigation.
